Where the geometry comes from

Three architectures

三種架構差在哪：放置層的數量與位置

程式裡三個架構共用同一套 core（graph / placement / routing / rule），差別幾乎全部集中在「有幾個 placement layer、它們在 z 軸的哪裡、彼此之間怎麼連」。

看 CFET 立體圖時注意這件事：把上面的 viewer 切到 CFET，會發現 N_ACTIVE(11/2) 和 P_ACTIVE(11/1) 的 x/y 邊界一模一樣 — 都是 x[15.5, 74.5] y[19, 125]。這不是畫錯，這正是 CFET：兩顆元件佔用同一塊平面面積，只差在 z。GDS 是平面格式，它只能用 datatype（/1 vs /2）來區分上下 tier，所以在 2D layout viewer 裡兩層是完全疊死的 — 立體圖才把這個差別攤開。

QFET 的 tier 跟 CFET 的 tier 不是同一回事。CFET 的兩個 tier 就是 P/N 之分（stacking_config 決定誰在上）。QFET 的兩個 tier 是晶圓的正面和背面，每一面都各自擺得下 PMOS 和 NMOS —— _compute_placement_row_indices 給的是 NMOS row 0 / PMOS row 2，跟 FinFET 一樣是 row 之分。所以在 QFET 裡 11/1 和 11/2 差在 Y，11/* 和 511/* 才是差在 z。

這也是為什麼背面 tier 是正面的鏡像：BCA1 宣告是 BM0 → BPC1，而 BM0 的 layer_number 比 BPC1 小（在下面），所以背面元件的接觸要往下走 —— BLISD1 在背面 diffusion 底下，而正面的 LISD1 在 diffusion 上面。

同理，CFET 的 gate 在 GDS 裡只有一個圖層 7/0（這顆 INV 上是 3 根柱子，每個 CPP 一根），而不是上下 tier 各一層：實體上 CFET 的 gate stack 本來就穿過上下兩顆元件，所以 writer 不需要（也不能）把它拆成兩層。我在立體圖裡把它的 z 區間設成 0 → 150 橫跨兩個 tier，就是要凸顯這件事。

Routing space

繞線空間是怎麼 initialize 出來的

整個 solver 看到的世界就是一張 LayeredGridGraph（core/graph.py）。節點是 (layer_idx, row, col)，邊是「同層可以走的一步」或「跨層的一個 via」。三個架構的 _init_graph() 做的事情就是算出每一層有哪些 row / col，然後把這張圖建出來。

  1. 讀 layer JSON → LayerStack

    core/entity.py:864 把 JSON 依 layer_type 拆成四類：metal（有 direction/pitch/offset/width，會進 graph）、via（只記 lower/upper，決定哪兩層相鄰）、virtual（純圖上的捷徑，沒有實體）、gds（solver 完全看不到，只給 GDS writer 用，例如 ACTIVE / WELL / FIN / SELECT）。

    metal 依 layer_number 由小到大排序，排完的 index 就是 LGG 的 z-index。QFET 的 .res 裡繞線線段寫 MET 5 / 6 / 7，對照 stack 就是 PC1 / M0 / M1 — 這個對應關係是自動長出來的，不是寫死的。

  2. 算 canvas 大小

    canvas_width  = num_col      × placement layer 的 pitch
canvas_height = num_rt_track × M0 的 pitch × 2

    QFET 這裡有一段值得看的註解（QFET/main.py:_compute_canvas_dimensions）：FinFET / CFET 都直接用 metal_layers[0].pitch，因為它們的第 0 層剛好就是 placement layer（PC / BPC）。但 QFET 的第 0 層是 BM1（背面金屬），用它會讓 canvas 窄掉 2/3、最後一個合法 column 被 [:-1] 砍掉。所以 QFET 改成明確去問 get_pitch(default_placement_layer)。這是三份 _init_graph 唯一一個「不能照抄」的地方。

  3. 倍解析度座標系（half-pitch convention）

    這是整份程式最容易看不懂的一招。Gate 落在整數 column 上，source/drain 落在兩個 gate 中間的半格上。為了讓兩者都是整數，模型把整個座標空間 放大兩倍：

    placement layer : pitch 保持原值      (本來就是半格解析度)
其他所有 layer  : pitch × 2         (對齊到 placement 格點)
offset          : × 2               (FinFET / QFET；CFET 沒有乘)

    下游要還原成實體 nm 時就除以 2 — 這就是三個 GDS writer 開頭都有的 SOLVER_RESCALE = 2.0。

    由此得到 column 的奇偶約定：偶數 index = gate 欄，奇數 index = source/drain 欄。_init_domain() 就是靠 col_indices_in_layer(layer, parity="even"/"odd") 把 CP-SAT 的 domain 切出來。

  4. 每層要有哪些 row / col

    規則很單純：V 方向的層貢獻 columns，H 方向的層貢獻 rows。缺的那一軸由 LayeredGridGraph._infer_from_nearest() 從 z 軸上最近、有該資料的層合併過來（不限相鄰 ±1，因為 QFET 有連續好幾層都是 V 方向）。

    CFET 在這裡加了一個很省的手腳（CFET/main.py:_init_graph）：上層 placement layer（PC）拿到全部 M0 rows，下層（BPC）只拿 頭尾兩個 boundary rows。中間的 row 對下層元件既沒有 pin 也接不到 via，留著只會讓模型變大。

  5. 建圖：節點、同層邊、via 邊

    節點   每層 product(rows, cols) 各一個 (z, r, c)
同層邊 direction=="H" → 只連左右鄰 col
         direction=="V" → 只連上下鄰 row
via 邊 連到 z±1，但前提是同一個 (r, c) 在那一層也存在

    最後這個條件就是 pitch 對齊在做的事：兩層的格點如果對不上，它們之間就長不出 via 邊。QFET 的 M1 用 pitch 42 / offset 21 而 M0 用 pitch 24，能不能打 via 完全由這個交集決定。

  6. 虛擬邊（virtual edge）：跳過中間層的捷徑

    當兩層在 z 上不相鄰、但實體上想讓它們直接通，就用 virtual edge。_build_graph 提供五種產生方式：

    • overlap — 只連 (r,c) 完全重疊的節點。QFET 的 VL1 (BPC1↔PC1) 用這個。
    • colwise — 同一個 column 上，下層每個 row 連上層每個 row。
    • sdcolwise — 同上，但只限下層的 奇數（S/D） column。
    • overlapGate — 只限指定的 gate columns（可再限 rows）。
    • boundary — 只連每個 column 的頭尾兩個共同 row。CFET 的 BPC↔M0 用這個，正好對應上一步只留 boundary rows 的決定。

    虛擬邊在 viewer 裡可以打開來看：切到 QFET、把 VL1 (virtual) 那列點亮，會看到一排黃色柱子從 BPC1 頂端貫穿到 PC1。那些柱子在真實製程裡不存在 — 沒有光罩、沒有幾何，它只是圖上的一條邊，走它要付 virtual_edge_cost（預設 5，比 metal 的 1 和 via 的 3 貴）。GDS 只有加 --draw-virtual 才會把它畫在 debug layer 700 上。

把 graph 建好之後才是約束。layer_to_kind（tech.py 的 property）把每一層標成 PLACE 或 ROUTE，core/routing.py 裡兩千多行的約束就靠這個分流：哪些層可以放電晶體、哪些層的邊要在 diffusion break 的 column 上被禁掉、哪些層算 M2 使用量上限。

Solve → GDS

GDS 是怎麼畫出來的

solver 解完不會直接吐 GDS。中間隔了一個純文字的 .res，這讓 GDS writer 完全不必碰 CP-SAT。

第一步：把解寫成 .res

write_finfet_result / write_cfet_result / write_qfet_result（各自的 util.py）把 solver 的變數值讀出來，做兩件事：把每顆電晶體的 x / y / (z) / flip / S,D,G 的 column 印成一張表；把所有 edge_vars == 1 的邊收集起來，用 _merge_collinear_edges() 把同層同 net 的共線邊串成一條長線段，再印成第二張表。

三個 tech 的表頭差異剛好是架構差異的縮影：

FinFET  Name  X  Y      Flip  Width Height  SrcCol ...
CFET    Name  X  Y      Flip  Width Height  SrcRow SrcCol ...
QFET    Name  X  Y  Z  Flip  Width Height  SrcCol ...

QFET 多的那個 Z 直接就是 placement tier 的名字（PC1 或 BPC1），從 lgg.idx_to_layer[z_idx] 查來的。我跑的這顆 INV_X1，兩顆電晶體都被放到 PC1（正面）— 反相器太小，solver 沒有理由動用背面 tier。

第二步：.res → KLayout

三個 writer 都是同一套骨架：_parse_result() 用正規表示式把兩張表讀回 NamedTuple，draw() 建立所有 layer index，然後依序畫 boundary → well/select → gate → fin → active/LISD → routing。

幾何全部靠幾個常數換算回 nm：

SOLVER_RESCALE = 2.0   倍解析度座標 ÷ 2 = 實體 nm
_ROUTE_X_OFFSET = -7   via / wire 錨在 landing via 的左下角
_ROUTE_Y_OFFSET = +29
_VIA_SIZE = 14         每個跨層落點都是 14×14 的接觸方塊

一條同層線段的盒子（gds_QFET_SH.py:_wire_box）：走向那一軸從起點的 via 涵蓋到終點的 via，垂直那一軸用該層自己的 width 對齊 via 中心，再各往外加 horizontal_enclosure / vertical_enclosure — 這兩個值是從 layer JSON 讀的（H 層 3/0、V 層 0.5/5），不是寫死的。

writerSCALEdbu1 writer 單位layer number 來源
gds_FinFET_SH.py40.00025= 1 nm寫死 self.layout.layer(15, 0) 這種呼叫
gds_CFET_SH.py100.0001= 1 nm同上，另加 6/0 = BPC、7/1 = PC
gds_QFET_SH.py40.00025= 1 nm讀 layer JSON 的 gds_layer / gds_datatype

SCALE 和 dbu 的組合不同但乘出來一樣（4×0.00025 = 10×0.0001 = 0.001µm），所以三份 GDS 的絕對尺寸是一致的 — 我把三個檔案讀進來換算後 cell 邊界都落在同一個 nm 空間，上面的立體圖才能直接並排比較。

最大的結構差異是最後一欄：QFET writer 已經把 GDS layer number 外部化到 layer JSON 了，FinFET / CFET 還是在 draw() 裡一行一行寫死。要換 PDK 的話，QFET 只要改 JSON，另外兩個得改程式。

Honest caveats

這張立體圖哪裡是真的、哪裡是我補的

來源
多邊形的 x / y 邊界完全真實 — 直接從三個 INV_X1.gds 用 KLayout API 抽出來，只做 dbu → nm 的換算。
層與層的先後順序真實 — 依 layer JSON 的 layer_number（即 LayerStack 排序後的 metal 順序）以及 via 的 lower_layer → upper_layer 鏈。
每層的 z 起點與厚度示意值，是我設的。layer JSON 裡完全沒有厚度資訊 — 它只描述平面上的 direction / pitch / offset / width。整個 SMTCell 是 2D 的：solver 的「層」是圖的 z-index，GDS 是平面格式。所以厚度必須由外部補，我按一般 4-track 先進製程的相對比例給值，只保證順序與誰跨越誰正確。
QFET 背面元件層是空的真實結果 — 這顆 INV_X1 兩顆電晶體都落在正面 PC1。ACTIVE_BACK_* / BSDT1 / BLISD1 沒有幾何，所以列在側欄但是空的（灰字斜體）。背面的 fin grid 和 BM0 電源軌有畫，因為 writer 不管有沒有元件都會鋪。

資料來源：本 repo 於 engine/ 目錄實跑 src.cellgen.run 三次（preset FinFET_4T_SH / CFET_4T_SH / QFET_4T_SH，cell INV_X1），再各跑一次對應的 src.cellgen.postprocess.gds_*_SH，最後用 KLayout Python API 把 GDS 的 polygon 全部 dump 成 JSON 內嵌進本頁。
